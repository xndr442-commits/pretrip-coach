# Full-build prompt

Paste as one message. Builds the whole app, but with mandatory checkpoints so
failures surface early instead of at the end.

---

Build the complete Pre-Trip Coach app described in `BUILD_SPEC.md`. All 14 steps of §12.

I want a working game I can run and adjust from, not a prototype. But build it in the
phases below and **stop at each checkpoint to report**, because a fault in early phases
silently invalidates everything after them.

## Ground rules

- **Never modify anything in `content/`.** It is generated by `scripts/` and validated
  by `scripts/validate_content.py`. Hand edits get overwritten. If you believe content
  is wrong, say so — do not change it.
- **Never hardcode a graded number.** Every threshold comes from
  `pretrip.en.json → standards`.
- **Run `python3 scripts/validate_content.py` in CI.** It must pass.
- If you stub or fake something, say so explicitly in your report. Do not present a
  stub as working.
- Commit each phase separately with a clear message.

## PHASE 1 — Foundation and grading

Steps 1–4: content loader with typed models and boot validation; the item screen
(photo, hotspot from `manifest.json`, concept pips, press-and-hold recording, live
transcript, typed fallback); the offline keyword grader; the AI grader behind a server
proxy.

**CHECKPOINT 1 — do not continue until you have run these and pasted the actual output:**

1. `lug_nuts`, typed input: `they're tight and all there`
   → must fill exactly 2 pips (`secure`, `all_present`), report `no_cracks` and `rust` missed.
2. `lug_nuts`, typed input: `they are not loose, none are missing, no cracks, and no rust streaks`
   → must fill all 4 pips. This is pure paraphrase — none of it matches `accept` literally.
3. `front_tire`, typed input: `the tire looks fine`
   → must fill 0 pips.
4. Same as (1) in Spanish: `están apretadas y todas presentes` → 2 pips.
5. Same as (1) in Portuguese: `estão apertadas e todas presentes` → 2 pips.

If (2) fails, the grader is too literal and will fail students who answered correctly.
If (3) passes any pip, it is too loose and the app is worthless. **Fix before Phase 2.**

## PHASE 2 — Modes and the air brake test

Steps 5–8: Learn Mode using `prompts/01_AI_INSTRUCTOR_SYSTEM_PROMPT.md` verbatim; Test
Mode with auto-fail handling; the air brake module; spaced repetition, XP and streaks.

Air brake specifics:
- Gate each phase on its `preconditions[]`. Wrong truck state → the phase refuses to
  start and explains why.
- `reading` steps need a spoken number validated against `standards` live. Out of range
  is a dangerous error, not a miss.
- `timer` steps run for real in Exam Simulator. Not skippable there.
- `"ordered": true` — a step out of sequence scores zero.
- Honour `variants` / `variant_must` for manual vs automatic transmission.

**CHECKPOINT 2:**
- Show an Exam Simulator run where a missed auto-fail ends the run immediately with a
  full-screen result naming the item.
- Show that a 60-second timer cannot be skipped in Exam Simulator.
- Show a spaced-repetition item scheduled for tomorrow after a miss.

## PHASE 4 — 3D

Steps 10–13.

**Build step 10 with a blocky placeholder truck first** — correct real-world
dimensions, all seven camera stations, and all 64 parts present as named nodes
`part_<item_id>` with simple colliders. Prove tap → photo → callout → grade works in 3D
before any real model is involved.

The supplied models are assessed in `docs/09_MODEL_ASSESSMENT.md`. Key facts: the Volvo
is ~961k triangles against a 150k budget and is **missing roughly 25 inspection parts**
(brake chambers, slack adjusters, leaf springs, king pin, glad hands, landing gear and
more). The trailer is a single un-inspectable mesh.

So: **generate proxy volumes for every missing part** — a simple box or cylinder at the
anatomically correct location on the tractor, named `part_<item_id>`, tappable. Tapping
opens the real photograph, which does the teaching. Write this as a reusable placement
script, not hand-placed geometry, so real meshes can be swapped in later.

Enforce the §11 budget in CI: ≤150k tris on screen, ≤80 draw calls, ≤120MB texture
memory, 30fps, ≤40MB 3D assets, ≤4s to first interaction. glTF/GLB + Draco + KTX2.
Baked lighting only. Per-station culling.

Ship the **photo-only fallback** — the app must be fully usable with 3D force-disabled.

**CHECKPOINT 4:** report measured triangle count, draw calls and frame rate. State
plainly which of the 64 parts are real geometry and which are proxies.
